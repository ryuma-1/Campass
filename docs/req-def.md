## 2. プロジェクト概要
### 2.1 背景・目的
* **独学における挫折の解消**: 独学において発生しやすい「次に何を学べればいいかわからない」「今やっている基礎学習が何に繋がっているか見えず飽きてしまう」という課題を解決します．
* **本質的な理解の支援**: 表面的なツールの使い方（ハウツー）の習得に留まらず，その裏側にある原理・原則を深く学ぶための独学支援システムを構築します．
* **最適な学習順序の自動化**: ユーザーが目指す「最終ゴール」から逆算し，必要な前提知識を基礎から順番に積み上げていく「トップダウン逆算型ボトムアップ学習」のプロセスを提供します．

### 2.2 ゴール・目指す姿
* ユーザーが学びたいことを自由に入力するだけで，LLM（生成AI）が学習内容の依存関係を計算し，迷子にならない「パーソナライズされたマップ」を動的に生成・提示できる状態を目指します．
* 学習の全体像を「マップ」として俯瞰でき，その上で「コンパス」が今進める場所を指し示すことで，全体を眺めながらも進む方向を見失わない状態を目指します．用語は GLOSSARY.md に従います．

### 2.3 ターゲットユーザー
* **目的意識のある独学者**: 「AIについて深く知りたい」「デザインに興味がある」など，ある程度の興味の種や問題意識（ゴール）を持っているユーザー．
* **本質を追求したい学習者**: 単なるツールの操作方法だけでなく，技術の背景や原理原則まで深くステップアップして学びたいユーザー．

## 3. システム化の範囲（スコープ）
### 3.1 対象範囲（インスコープ）
* ユーザーの入力から，外部の LLM を活用してマップを動的に生成する機能．
* 複雑なマップを認知負荷の低い画面で見せる Web アプリケーションの構築．
* ターミナルから Web と同じように学習を進められる CLI クライアントの構築．
* ユーザーの理解度や記述式回答，選択した難易度に応じて，プロセスを最適化・動的アップデートする機能．

### 3.2 対象外範囲（アウトスコープ）
* 独自のLLMモデルの構築（既存の外部LLM APIであるChatGPT やClaude やGemini などを活用することを前提とする）．
* 各学習ステップにおける，詳細な教材コンテンツそのものの独自制作（まずは外部記事へのリンクやAIによる概要生成，課題の提示を主軸とする）．

## 5. 非機能要件

機能面以外でシステムが満たすべき品質，性能，および運用の要件です．

### 5.1 動作環境（システム特性）
* **対応ブラウザ / OS:**
  * Google Chrome（最新版）
  * Microsoft Edge（最新版）
  * iOS Safari
  * Android Chrome
* **デバイス:** PC，スマートフォン（レスポンシブ対応）
* **CLI（F-014）:** Linux，macOS，Windows．言語の実行環境などを別にインストールせずに使えること．
* **画面表示の最適化（認知負荷の軽減）:** マップを開いた直後は情報量を絞り，学習者の現在地と今進める場所に注目できること．全体像はユーザーが自分で広げて眺められること．これにより，独学時の認知負荷を最小限に抑える．

### 5.2 性能・拡張性
* **マップ生成の待ち時間:**
  * マップの生成には数十秒かかり得る．生成の終わりを待たせず，できたノードから順に画面に表示し，ユーザーが最初の一歩をすぐに読み始められること．
* **同時接続数（スモールスタート仕様）:**
  * 初期リリース時は検証・スモールスタートを前提としたインフラ構成とする．
    * **通常時:** 100 アクティブユーザー / 日
    * **最大（ピーク時）:** 1,000 アクティブユーザー / 日
  * ※将来的な大規模公開やSNS等での拡散（バズ）に伴うアクセス急増時は，サーバーを増強して柔軟に拡張できること．
* **拡張性:**
  * ユーザーが複数のゴールを並行して達成できるよう，同じ内容のノードを複数のマップで共有できること（F-015）．

### 5.3 セキュリティ・データ保護
* **API キーの秘匿化:**
  * サービスが使う外部 LLM の API キーは，サーバーの外（ブラウザや CLI）へ絶対に出さないこと．
  * ユーザーが自分の API キーを設定する場合（F-020），キーがブラウザを通るのは，ユーザーが入力して一度送るときだけとする．保存したキーはどの画面や応答にも出さず，ログにも残さず，保存先が漏れても読めない形で保存すること．
* **データ保護（学習に使わせない API のプラン）:**
  * ユーザーの自由記述ワーク（言語化入力）に含まれ得る個人情報や秘密情報を外部LLMの学習に使わせないため，本番のサービスでは，入出力をAIモデルの学習に使わない契約で LLM を使う．開発中（テスト用のデータしか送らない）は問わない．
  * ユーザーが自分の API キーを設定した場合（F-020），そのキーで送る入出力は上の約束の対象外とし，ユーザーとその会社との契約の規約に従う．設定画面でそのことを示す．

### 5.4 運用・保守
* **プロンプトのバージョン管理:**
  * AIへの指示文（プロンプト）の変更は，生成されるマップの品質に直結するため，プログラムとは切り離して版を管理し，システムを止めずにプロンプトのA/Bテストやチューニングができること．
* **マップのデータ保持期間:**
  * ユーザーが作成した複数の「マップ」，およびそれに紐づく「動的な学習ログ・進捗ステータス」は，ユーザーが自ら削除するか，退会するまで永続保持する．
