# 実装計画: シラバス生成 SSE のイベント形式を design_doc に定義する

## 元Issue
- #2: [Task] シラバス生成 SSE のイベント形式を定義する
- https://github.com/ryuma-1/Campass/issues/2

## 概要
`POST /api/notebooks/:id/syllabus`（SSE）について，イベント名，ペイロード，終了通知，エラー通知の形式を `doc/design_doc.md` 4.3.1 に定義し，レスポンス例を追加する．ドキュメントのみの変更で，コードは変更しない．フロントエンドと CLI の SSE 受信処理が依存する契約を，実装前に確定させることが目的である．

## 要件
- ノードイベント，リンク提案，生成完了，エラーの各イベント名とペイロードを 4.3.1 に記載する．
- SSE のレスポンス例（ストリームの生テキスト）を追加する．
- 既存の制約を落とさない．
  - 1イベントは完成した1ノードに対応し，トークン断片は送らない（4.3.2）．
  - パース失敗は最大2回リトライし，それでも失敗した場合はクライアントに明示的なエラーを返す．不完全なデータを成功として扱わない．
  - DAG 違反（循環，未知の前提 id）は検証エラーとして扱い，黙って除去・修正しない．
  - API キー，埋め込みベクトル，内部情報はペイロードに含めない．
- 参照元は 4.3.1，4.3.2，4.5.6 である．
- 4.5.6 の CLI 受信方式（空行区切り，複数 `data:` 行を連結して JSON デコード）と矛盾しない形式にする．

## 決定事項（ユーザー確認済み）
- イベント名は短い名前にする：`node` / `link_proposal` / `done` / `error`．
- リンク提案は `node` に入れ子にせず，独立イベント `link_proposal` として，該当 `node` イベントの直後に送る．ペイロードは `GET /api/cross_notebook_links?status=proposed` の `proposals` 要素と同形にする．4.3.1 の表の「イベント内に含む場合がある」という文言はこれに合わせて直す．

## 実装方針
1つのフェーズで進める．対象は `doc/design_doc.md` のみである．

1. 4.3.1 の API 表とレスポンス例の並びに，`POST /api/notebooks/:id/syllabus` の「SSE イベント形式」を追加する．既存の `**… レスポンス例**` 見出しの体裁に合わせる．
2. イベント種別：
   - `node`: 完成した1ノード．`id`，`title`，`summary`，`prerequisites`，`route_type`，`importance_score`，`depth_level`，`related_main_node_id` を含む．ID はDB保存後のIDとし，`map` のノード表現と整合させる．
   - `link_proposal`: 4.2.7 で検出した提案．`link_id`，`similarity_score`，`source`，`target`．
   - `done`: 生成完了．`notebook_id`，`status: "ready"`，ノード数程度を含める．
   - `error`: `code`，`message`，`retryable`．パース失敗のリトライ上限超過，DAG 検証エラー，LLM API エラー，内部エラーを区別できる最小限のコードを定める．内部例外の詳細やキーは含めない．
3. 共通事項：`Content-Type: text/event-stream`，`event:` 行と `data:` 行（JSON1行），空行区切り．`done` と `error` は終端イベントで，その後サーバーは接続を閉じる．任意でハートビート（コメント行）．認証は CLI の Bearer のみ記載し，フロントエンドは未決と明記する．
4. 完全なストリーム例を追加する：`node` ×数件，`link_proposal`，`done` の正常系と，`error` で終わる異常系．
5. 関連箇所の整合：4.3.1 の表の概要文，4.3.2 にイベント形式への参照を1文，4.5.6 にイベント名での分岐と未知イベントの扱い，4.5.7 の記述．
6. 9章の「SSE のイベント形式」を解決済みとして削除する（過去の解決済み論点の扱い方に合わせる）．
7. 10章の変更履歴に新バージョンの行を追加する（日付は作業日，作成者は既存行に合わせる）．
8. 句読点は「，」「．」に統一する．

## リスク・確認事項
- 生成中の離脱・再訪・Ctrl+C の扱いは 9章で未決である．再開用の `id:` / `Last-Event-ID` は入れず，再接続の挙動は 9章の論点に残す．
- 途中失敗時のロールバック方針は未決である（5.2）．`error` に「保存済みノードが残るか」を示す項目は入れない．
- フロントエンドの認証方式が未決のため，ブラウザ側の SSE 認証は「未決」と明記する．ブラウザの `EventSource` は POST やヘッダー指定ができないため `fetch` ストリーム等が必要になる点は注記に留める．
- `error` のコード体系は最小限（パース／検証／LLM API／内部）に留める．
